# Принести облаку немного любви ♡

Спасибо, что помогаете LoveCloud становиться уютнее.
Проект команды **neo_mei** объединяет хранилище, дневник и планы одной пары.

## С чего начать

В issue опишите идею или ошибку: что делали, чего ожидали и что произошло.
Для ошибки интерфейса полезны версия браузера, размер экрана и скриншот.
Секреты, личные фотографии и установочные ссылки в issue не прикладываем.

Перед большим изменением удобно обсудить его в issue. Для небольшой
исправленной ошибки достаточно pull request с объяснением и проверкой.

## Работать над своим облаком

Запуск описан в [README](README.md#start). Технические подробности — в
[гайде по размещению](docs/SELF_HOSTING.md) и [документации API](docs/API.md).
Используйте отдельную установку с вымышленной парой для разработки и скриншотов.

| Где | Что находится |
| --- | --- |
| `frontend/` | Next.js, React, стили, локализация и иллюстрации. |
| `backend/` | ASP.NET Core, API, доступ к данным и миграции. |
| `ops/`, `compose*.yaml` | nginx, HTTPS, Tailscale и Docker. |
| `scripts/`, `tests/` | Установка, резервные копии и проверки. |
| `docs/` | Публичные инструкции и визуальный стиль. |

## Что проверить

Для интерфейса:

```sh
npm ci --prefix frontend
npm run typecheck --prefix frontend
npm run build --prefix frontend
```

Для связанных изменений API и хранилища в PowerShell7 с Node.js24:

```powershell
docker compose build
./scripts/test.ps1
./scripts/test-onboarding.ps1
```

Сквозные тесты создают отдельные одноразовые проекты на3212/3213.
Они используют синтетические данные. Не направляйте их на своё облако.

Проверяйте сценарии, которые меняете: успешный результат, ошибку, пустое
состояние и права доступа. Миграции должны сохранять существующие данные.

## Сохранить характер LoveCloud

Следуйте [визуальному стилю](docs/BRAND.md). Новые подписи добавляйте на русском
и английском. Проверяйте клавиатуру, фокус, мобильную раскладку и reduced-motion.
Изменения интерфейса сопровождайте снимками до/после с вымышленными данными.

Временные состояния честно показывают загрузку и ошибки. Доступ к личным
файлам и сюрпризам проверяется сервером. Внешний вид не заменяет авторизацию.

## Оставить понятную историю

Используем [романтичный гайд по коммитам](docs/COMMIT_STYLE.md):

```text
feat(feed): 💌 add replies to love notes
```

В pull request объясните проблему, итоговое поведение и проверку.
Укажите миграции или действия для обновления, если они нужны.
Сообщения коммитов, включая тело и BREAKING CHANGE, пишем только на английском.
Подписывайте изменения своим Git-профилем.
